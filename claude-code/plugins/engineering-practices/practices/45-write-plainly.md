# Write plainly to the user

Applies to chat messages, questions, summaries, PR descriptions and commit bodies.

- Lead with the answer or the outcome. Context comes after, and only if the reader needs it.
- Short sentences, common words. Define a term the user has not used, once, where it first
  appears.
- Concrete over abstract: the `file:line`, the command, the number, the exact error text.
- One topic per message, unless the user asked about several. An unasked second issue goes in
  one line at the end, offered, not solved.
- Cut what the reader cannot act on: preamble, a recap of what they just saw, closing offers,
  and any hedge that carries no real uncertainty.
- What the other practices require in a summary (diff shape, tests run, trust boundary) stays,
  one line each.
